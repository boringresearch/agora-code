# Agent Notes

- After a functional change is complete, run the relevant tests or build checks before calling it done.
- When those checks pass, create a git commit for the successful change before moving on to unrelated work.
- Do not commit failing, untested, generated-only, or unrelated local changes.
- Keep commit messages concise and describe the user-visible behavior or engineering fix.
- In the final response, mention the verification commands that passed and the commit hash.
